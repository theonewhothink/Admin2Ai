# Android share intent and scanner notes (§11, §12)

Nothing in this folder is compiled into the app. The Android project is
generated by `expo prebuild`; these notes record what the config plugins set and
the known limits.

## Share intent

`expo-share-intent` adds intent filters to `MainActivity`
(`android:launchMode="singleTask"`), configured in `mobile/app.json`:

| Action | MIME types |
| --- | --- |
| `android.intent.action.SEND` | `text/*`, `image/*`, `application/pdf`, `message/rfc822`, `application/xml`, `text/xml` |
| `android.intent.action.SEND_MULTIPLE` | `image/*`, `application/pdf` |

The plugin's TypeScript options list only wildcard types, but it writes each
string straight into the manifest, and the native module treats every
non-`text/plain` share as files. PDFs, `.eml` and XML therefore arrive as files
with their MIME type.

Limits, on purpose:

- We do not register `*/*`. A mixed multi-file share (say a PDF and a photo)
  is announced by Android with a common type such as `*/*`, so Back Office is
  not offered for it; the owner shares the files one kind at a time. Adding
  `*/*` would make the app appear for every share (videos, audio, contacts),
  which the app would then have to refuse.
- Content from other apps is copied into the app cache by the native module.
  After sealing, `discardTemporary` deletes only copies inside the app's own
  cache; the sender's original is never touched.

## Document scanner

`react-native-document-scanner-plugin` uses the Google ML Kit Document Scanner
(auto-capture, edge detection, crop, perspective correction, rotation,
multi-page). It needs Google Play services; the scanner module downloads on
first use. Without Play services the scan returns "unavailable" and the Scan
screen says so plainly.

## Permissions

`app.json` blocks `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE` and
`RECORD_AUDIO`, which `expo-camera` would otherwise add. The app needs only
`CAMERA`, `INTERNET`, `USE_BIOMETRIC` / `USE_FINGERPRINT` (§52 least privilege).
`android.allowBackup` is `false`: sealed evidence and the queue index are
useless without the Keystore key and should not leave the device in backups.
